# Kotlin Multiplatform — Generated API

Describes the shape of classes and interfaces generated by `resource-kotlin-mpp`. Read this when a developer asks how to instantiate or extend the generated repository classes.

For plugin configuration (DSL, parameters, source setup) see `references/resource-kotlin-mpp.md`.

---

## Class naming

Generated names are controlled by three parameters in `kotlinMultiplatform { }`:

| Parameter | Controls |
|---|---|
| `repositoryInterface` | Name of the common interface |
| `repositoryClass` | Name of the platform implementation class |
| `repositoryPackage` | Package prepended when either name above is a simple (non-canonical) name. Defaults to `project.group`. |

If `repositoryInterface = "StringRepository"` and `repositoryPackage = "com.example"`, the generated interface is `com.example.StringRepository`. If `repositoryInterface` is already canonical (contains `.`), the package is ignored.

Each platform block can override the name individually via its action lambda:

```kotlin
kotlinMultiplatform {
    repositoryInterface = "StringRepository"
    repositoryClass = "StringRepositoryImpl"
    repositoryPackage = "com.example"

    common { interfaceName = "IStringRepository"; interfacePackage = "com.example.api" }
    android { className = "AndroidStringRepository"; classPackage = "com.example.android" }
    ios { className = "IosStringRepository" }   // classPackage falls back to repositoryPackage
}
```

For the `common` block: `interfaceName` / `interfacePackage`.
For all other blocks (`android`, `ios`, `js`, `absKeyValue`, `absStatic`, `absProxy`): `className` / `classPackage`.

## Key → member name mapping

Every string key is converted to a Kotlin identifier by `TextUtils.keyToProperty`:

1. Any run of non-alphanumeric characters is collapsed to a single `_`.
2. If the result starts with a digit, a `_` is prepended.
3. Trailing underscores are stripped.
4. The whole name is lowercased.

Examples:

| Key | Member name |
|---|---|
| `title` | `title` |
| `item_count` | `item_count` |
| `Some Value` | `some_value` |
| `some__value__` | `some_value` |
| `1_value` | `_1_value` |
| `formula x = (y + 3/2) * z.` | `formula_x_y_3_2_z` |

**What gets generated per key:**

- **Simple string** — a `val` property.
- **Formatted string** (contains format arguments) — both a `val` property (raw template) **and** a `fun` with the same name whose parameters match the format arguments.
- **Plural string** — a `fun` only; the first parameter is always `count: Long` (or `Int` if the source argument is typed as `Int`), followed by any additional format arguments.

**Function parameter names** follow formatting type conventions:

- `JavaFormattingType` (`%s`, `%d`, …): positional names built from the Java type shorthand + 1-based index — `s1`, `d2`, `s3`, etc.
- `WebFormattingType` (`{{name}}`): the name from the template placeholder is used as-is.
- Plural `count` argument: always named `count` regardless of formatting type.

Given keys `title` (simple), `greeting` (formatted — `"Hello, %s!"`), and `itemCount` (plural), LocoLaser generates the following.

## Common interface (`commonMain`)

```kotlin
interface StringRepository {
    val title: String
    fun greeting(s1: String): String
    fun itemCount(count: Long): String
}
```

## Android implementation (`androidMain`)

Reads from `strings.xml`. Constructor accepts `Context`.

## iOS implementation (`iosMain`)

Reads from `Localizable.strings` / `.stringsdict`. Constructors:
- `constructor()` — uses `NSBundle.mainBundle()` and `"Localizable"` table
- `constructor(bundle: NSBundle)`
- `constructor(tableName: String)`
- `constructor(bundle: NSBundle, tableName: String)`

## JS implementation (`jsMain`)

Reads from `i18next`. Constructor accepts `I18n`.

## `absKeyValue` implementation

Concrete class implementing the interface via a string provider.

With `NoFormattingType` (default):
- constructor accepts `StringProvider`;
- format arguments are ignored — formatted functions call `getString(key)` without substitution.

With `JavaFormattingType`:
- constructor accepts `IndexFormattedStringProvider`;
- format arguments forwarded positionally — `getString(key, arg1, arg2, ...)` / `getPluralString(key, count)`.

With `WebFormattingType`:
- constructor accepts `NameFormattedStringProvider`;
- format arguments forwarded as named pairs — `getString(key, Pair("s1", arg1), Pair("d2", arg2))` / `getPluralString(key, count)`.

## `absStatic` implementation

Abstract class returning hardcoded source string values. Must implement:
- `getQuantity(count: Long): Quantity` — selects the plural form

With `NoFormattingType` (default):
- formatted functions return the raw template string.

With `JavaFormattingType`: additionally must implement:
- `formatString(string: String, vararg args: Any): String` — controls argument substitution (can be trivial in test stubs).

With `WebFormattingType`: additionally must implement:
- `formatString(string: String, vararg args: Pair<String, Any>): String` — same purpose, but arguments are named pairs; the template uses `{{name}}` placeholders.

## `absProxy` implementation

Abstract class delegating all calls to `abstract val stringRepository: StringRepository`.
